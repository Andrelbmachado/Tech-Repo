# Skill: Arquitetura de software

Projetar e documentar arquitetura de software.

## Quando usar

Decisões estruturais: módulos, serviços, integrações, requisitos não funcionais.

## Conceitos principais

- Atributos de qualidade (desempenho, disponibilidade, segurança, manutenibilidade)
- Estilos: camadas, hexagonal, microsserviços, event-driven
- Acoplamento e coesão
- Decisões arquiteturais registradas (ADR)
- Visões e diagramas (contexto, contêiner, componente)

## Boas práticas

- Registre decisões e alternativas em ADRs
- Comece simples (monólito modular) e evolua com dados
- Defina limites claros entre módulos
- Explicite requisitos não funcionais mensuráveis
- Revise a arquitetura quando requisitos mudarem

## Armadilhas comuns

- Microsserviços prematuros
- Arquitetura não documentada
- Otimizar para requisitos hipotéticos
